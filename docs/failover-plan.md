# ocspeed 故障转移增强方案（v3.4 规划稿）

> 本文只做规划，未改动任何脚本行为。所有数字取自 2026-09-16 真机实测。
> 结论先行：**当前故障转移是关着的**，所以第 3 节 P0 是收益最大的一步。

---

## 0. 一句话结论

| 项 | 现状 | 影响 |
|---|---|---|
| `failover_enable` | **0** | 断线不会自动切 |
| `backup_enable` | **0** | 备用名单不预选，`backup.json` 为空 |
| crontab | 只剩 `#ocspeed-auto` 一条（30 分钟全量测速） | **节点故障 → 恢复最长 30 分钟** |
| `宝贝云` 组类型 | `Selector`（45 个成员） | mihomo 自己**不会**切，ocspeed 是唯一的自动机制 |
| `[failover]` 日志 | 一条都没有 | 说明这条通道从未真正跑起来 |

全量测速顺带能兜底（当前节点测不出结果时会切走），但它 30 分钟才跑一次。
所以「打开 failover + 预选备用池」是当前性价比最高的一步，**改动量几乎为零**
（脚本里 `cron_apply` / `failover_check` / `backup_do` 都已实现且自洽）。

## 1. 现状盘点（用数据说话）

数据来源：`/etc/openclash-helper/history.log` 最近 10 轮、`/var/log/ocspeed.log`、
`GET /proxies/宝贝云`、`GET /configs`。

### 1.1 切换过于频繁（churn）

10 轮里 **6 轮触发了 switch=1**。当选节点（初赛延迟）依次是：

```
570  567  515  503  529  551  520  547  479  539   (ms)
 ^切  ^切   —   ^切  ^切   —    —   ^切   —   ^切
```

相邻轮之间只差十几到几十毫秒。`threshold=50` 意味着「有节点比当前快 50ms 就切」，
而 top5 的离散度本身就在 10~90ms 量级 —— 于是**几乎每轮都在换节点**。
每次切换都会打断所有已建立的 TCP 连接（视频重新缓冲、下载中断），
代价远大于那十几毫秒的收益。

### 1.2 「失效节点数」是噪声，不是故障证据

同一份订阅，20 分钟内每轮的可用/失效数：

```
可用: 50 41 46 46 48 47 56 44 48 44
失效: 15 24 19 19 17 18  9 21 17 21
```

失效数在 9~24 之间反复摆动，**上一轮判死的节点下一轮就活了**。
结论：单轮全超时不能作为「节点故障」的判据，必须多探针 + 多轮证据。

### 1.3 备用池有「同源」盲区

节点名是结构化字段：`L1|<落地>|<线路类型>|流媒体|<倍率>`，例如

```
L1|新加坡01|中转|流媒体|4x      L1|新加坡01|直连|流媒体|2x
L1|日本03|中转|流媒体|4x        L1|日本03|直连|流媒体|2x
```

实测分布：`中转` 22 个、`直连` 15 个、`流媒体` 5 个、`免流` 2 个；
**每个落地几乎都成对出现（中转 + 直连两条线路）**。

而 `backup_do` 现在是「按上次延迟升序取前 `backup_probe=8` 个、保留最快 3 个」。
按延迟排序时，同一落地的两条线路往往紧挨在一起 ——
**备用池极可能全是同一个落地的中转+直连**。该落地一挂，备用池全军覆没。

### 1.4 首要判据仍是单探针

`failover_check` 第一步只探 `test_url`（`gstatic/generate_204`）。
代码里已有 `probe_delay_multi` 的多探测点回退（最多 3 个备用站），
但它只是「主探针拿不到结果时的补救」，**判定逻辑本身仍是单探针**：
该 URL 一旦被干扰或被节点侧缓存，所有节点都返回空 → 会被当成「所有节点都挂了」。

### 1.5 切过去就不管了

切换成功后只写一个 `last_failover` 时间戳，**不验证新节点是否真的可用、
也不比较是否比原节点更差**。历史上（代码注释里记着）8 次切换有 4 次是劣化。

### 1.6 静默期会挡住真故障

`failover_quiet=90`：全量测速结束后 90 秒内，`failover_check` 直接 `return 0`
（这条是为了躲开测速尾巴造成的伪故障，是必要的）。但如果真断网恰好落在这 90 秒里，
用户最多白等 90 秒 —— 因为「静默期」不区分信号强弱。

### 1.7 备用探测是串行的

备用名单逐个 `probe_delay_multi`（每次约 2.3s），3 个约 7s；
名单过期退回 Top5 串行探测要 15s+。而 `backup_do` 里**已经有 4 路并发的写法**可抄。

### 1.8 没有结构化故障历史

只有 `$DATA/last_failover` 一个时间戳 + 文本日志，
无法回答「这一周切了几次、几次是误切、最近一次为什么切」。

## 2. 目标（可验收）

| 指标 | 现状 | 目标 |
|---|---|---|
| MTTR（节点故障 → 流量恢复） | 最坏 30 分钟 | **< 60 秒** |
| 误切率（切完 5 分钟内又切回原节点） | 约 6/10 轮都在切 | **< 10%** |
| 单点误判（探测点自身问题导致的切换） | 无防护 | **0** |
| 可解释性 | 只有一句文本日志 | 每次切换/跳过都能在 WebUI 看到判据 |

## 3. 方案分层

### P0 —— 先让它真的跑起来（改动最小、收益最大）

**P0-1 打开开关 + 重建 cron**

```sh
uci set ocspeed.main.failover_enable=1
uci set ocspeed.main.backup_enable=1
uci commit ocspeed
/usr/libexec/openclash-helper/speedswitch.sh cron
```

`cron_apply` 会自动补齐 `#ocspeed-failover`（每分钟）与 `#ocspeed-backup`（每分钟自检间隔）两条。

**P0-2 本地链路对照探针（新增判据，最关键的一个）**

已经确认这台机器**没有开 TUN**（`/configs` 返回 `tun.enable=false`，
`proxy_mode=rule`，走 iptables REDIRECT 2 条规则），所以：

- `ping -c2 -W2 223.5.5.5` 是**真实直连**（实测 2/2 通，8.8ms，走 eth0）
- `ubus call network.interface.wan status` 的 `up`（实测 `true`，proto=dhcp，device=eth0）
- ⚠️ **不要用 DNS 做这个判断**：`enable_redirect_dns=1`、dns_port=7874，
  DNS 是被 mihomo 劫持的，走代理，会跟着一起挂

判据：

```
WAN up  且 直连 ping 通   → 本机出口正常，问题在代理侧 → 可以切
WAN down 或 直连 ping 不通 → 本机/光猫/上游问题，切节点没用 → 只告警不切
```

这条能直接消灭「上游整体拥塞时白白切一圈、还浪费一个冷却周期」的情况。

**P0-3 多探针共识**

故障判定改为「≥2 个探针同时失败」，探针集合 = `test_url` + 一个业务域名
（建议 `gemini.google.com`，与决赛一致）。只有一个失败 → 只记日志，不判故障。

**P0-4 硬故障突破静默期**

静默期只挡弱信号。定义硬故障：
`连续 N=3 次（间隔 20s）多探针全失败`，或 `WAN up 且全部探针全失败`。
命中硬故障时立刻转移，不等静默期、不等冷却。

---

### P1 —— 判定质量

**P1-1 备用池同源约束**

- 落地 = 名字第 2 字段，线路类型 = 第 3 字段
- 取备用池时按落地去重，**同一落地最多 1 个**，且优先排除与当前节点同落地的
  （当前 `L1|新加坡01|中转` → 先排除 `L1|新加坡01|直连`）
- 新增 UCI：`failover_avoid_same_landing`（默认 `1`）；
  若候选里只剩同落地节点，则允许降级使用并打日志

**P1-2 切换要有净收益**

把「best 比当前快 50ms 就切」改成两个条件的**与**：

```
bestd <= curd * good_ratio        (默认 0.7)
curd - bestd >= min_gain          (默认 30ms)
```

例外：当前节点判定为**不可用**（多探针全失败）时无脑切，不看收益。
这一条直接针对 1.1 的 churn。
新增 UCI：`switch_min_gain`、`switch_good_ratio`。

**P1-3 切换后验证 + 快速回滚**

```
切到 best
  → 3s 后复测 best
      ├─ 可用            → 结束（若比原节点慢且原节点已恢复 → 回滚，记 rollback）
      └─ 仍不可用        → 从剩余备用里再选一个（最多重试 2 次）
```

**P1-4 备用探测并行化**

把备用名单的 `while read … probe_delay_multi … done` 改成 4 路并发
（照抄 `backup_do` 里的 `( … ) &` + `wait` 计数写法），MTTR 从 ~15s 降到 ~5s。

---

### P2 —— 可观测与自适应

**P2-1 结构化故障历史**

`$DATA/failover.log` 写 JSONL：

```json
{"ts":1789493360,"act":"switch","why":"probe-x2","from":"L1|新加坡01|中转|流媒体|4x","fromd":null,"to":"L1|日本03|中转|流媒体|4x","tod":612,"cost":4.1,"local":"wan-up,ping-8.8ms"}
```

`act` ∈ `switch` / `rollback` / `skip-local` / `skip-noise` / `skip-cooldown`。
WebUI 加「故障转移」面板：最近 10 次 + 切换成功率 + 误切率。

**P2-2 阈值自适应**

现在 `threshold=50` 是拍的。可以用「同落地的中转/直连两条线路」做噪声基线 ——
它们上游相同，延迟差基本只反映测量噪声。取最近 N 轮的差值中位数作为
`min_gain` 的下限，避免用低于噪声的阈值做决策。

**P2-3 分类感知转移**

分类测速已经能给出「AI / 视频 / 流媒体 各自的最佳节点与可用性」。
下一步可把「AI 类站点全超时但 gstatic 正常」纳入判据 ——
这种情况不必动主组，只切 AI 流量的分组即可。
（依赖：用户侧把 AI 流量分流到独立策略组，属配置项。）

## 4. 改动点与风险

| 项 | 改动位置 | 风险 | 回滚 |
|---|---|---|---|
| P0-1 | UCI + `cron_apply` | 开始自动切节点 | `uci set failover_enable=0` 再 `cron` |
| P0-2 | `failover_check` 开头新增 `local_link_ok()` | 误判 WAN 状态会阻止正常转移 | 函数内加 `return 0` 开关 |
| P0-3 | `failover_check` 探针段 | 判据变严 → 可能变迟钝 | 探针数降回 1 |
| P0-4 | 静默期判断 | 硬故障判据太松会误切 | 提高 N 或关掉该项 |
| P1-1 | `backup_do` 候选池 | 候选变少 → 备用池可能不足 3 个 | 关闭 `avoid_same_landing` |
| P1-2 | `speedtest_full` 切换段 | 太保守会错过真实优化机会 | 调小 `min_gain` |
| P1-3 | `failover_check` 尾部 | 多一次探测 = MTTR +3s | 跳过验证 |
| P2-1 | 新增写日志 | 无 | 无副作用 |
| P2-2 | 阈值计算 | 基线估计偏差 | 回到固定 50ms |

所有改动都落在 `speedswitch.sh` 一个文件里，且都是「先加开关、默认关」的形式，
可以逐条灰度。

---

## 5. 需要你决策的点

1. **是否现在就打开 `failover_enable` / `backup_enable`？**（会开始自动切节点）
2. 切换收益阈值取多少？建议 `min_gain=30ms` + `good_ratio=0.7`。
3. **允许「降级切换」吗？** 现在代码是允许的（阈值内没有节点时，切到最快的一个，
   哪怕它明显更慢）。断网时这比干等好，但会带来一次「切到慢节点」的体验。
4. 同源约束的强度：同落地是**绝对排除**，还是**仅在有多落地候选时回避**？
5. MTTR 目标确认：60 秒是否可接受（关系到探测并发度与重试次数）。

---

## 6. 怎么验收（不用等真故障）

- **离线回放**：拿 `history.log` 的历史 top5 数据，用新旧两套判据各跑一遍，
  对比「切换次数」与「切换后是否更差」。这一条**现在就能做，零风险**。
- **合成故障**：手动把当前节点切到一个已知死节点（`PUT /proxies/组`），
  看多久恢复；或临时用 iptables 丢包模拟。
- **本地链路对照**：拔网线 / 关上游光猫，确认系统**不切节点**而是告警。
